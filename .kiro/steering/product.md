# MatchMon · 제품 개요 (product)

> 이 문서는 제품 방향과 사용자 흐름을 정리한다. "실제 구현"과 "향후 계획"을 구분해 기록하며,
> 코드로 확인되지 않은 비즈니스 정책은 추측하지 않는다.

## 1. 서비스 목적

MatchMon은 아마추어 축구·풋살 **대회 운영 플랫폼**이다. 팀·선수 등록, 대회 생성 및 참가,
경기 일정과 대진표, 경기 결과 입력, 순위·득점 랭킹을 한곳에서 다루는 것을 목표로 한다.

> 참고: 이 저장소는 **프런트엔드 단독**이다. 백엔드(API 서버)는 별도 저장소에 있으며,
> 프런트엔드는 그 백엔드 계약(HTTP API)에 맞춰 동작한다.

## 2. 사용자 역할 (3-Role)

라우터와 내비게이션이 역할별로 분리되어 있다. (`src/router/path.tsx`, `src/router/index.tsx`)

- **일반 유저 (NU, Normal User)**: 팀·선수·대회 조회, 랭킹, 대진표 열람. 대회 **생성 권한은 없음**.
- **대회 운영자 (CA, Competition Admin / `competitionUser`)**: 참가팀 관리, 매칭, 대진표,
  경기 기록(결과) 입력, 순위 확인.
- **개발자 / 관리자 (`admin`)**: 대회·유저·팀·선수 전체 관리.

> 코드 주석(`path.tsx`)에 따르면, 참가비 등의 이유로 일반 유저는 대회를 생성할 수 없고
> 대회 운영자 계정에서만 생성한다. 구체적 과금/정산 정책은 **코드로 확인되지 않음**.

## 3. 핵심 사용 흐름

### 일반 유저
팀/선수/대회 조회 → 대진표 열람 → 랭킹 확인.

### 대회 운영자
대회 선택 → 참가팀 관리 → (조별리그/매칭 구성) → 경기 일정 생성 →
경기 진행 후 **경기 결과 입력** → 순위·랭킹 반영.

> 전체 운영 흐름(대회 생성 → 팀 등록 → 경기 진행 → 결과 입력 → 순위 확인)의 골격은 존재하나,
> 결과 입력과 순위 단계가 아직 완성되지 않았다(아래 4절 참고).

## 4. 구현 현황

### 구현된 기능 (코드로 확인)
- 역할 기반 라우팅 및 보호 라우트 (`PrivateRoute`, `ProtectedLayout`)
- 인증(로그인/회원가입/프로필 조회) — `src/auth/AuthService.ts`
- 대회·팀·선수·조별리그·토너먼트·경기 일정·경기 설정 API 레이어와 react-query 훅
- 경기 결과 **목록 조회 화면** — `src/pages/competitionUser/matchReport/index.tsx`
- 공통 컴포넌트(Button, Select, Pagination, Tabs, DateTimePicker, Loading) + Storybook

### 미완성 / 미연결 기능 (코드로 확인)
- **경기 결과 입력 화면** (`matchReport/Detail.tsx`): 입력 UI와 저장 로직이 주석 처리되어 있고,
  잘못된 필드 접근(`matchScheduleId` 등)으로 선택 경기를 찾지 못한다. 저장 훅
  (`useCreateMatchResult`/`useUpdateMatchResult`)이 정의만 되고 호출되지 않는다.
- **선수별 득점 입력**: `ScoreBoard.tsx`에 선수별 골 카운터 UI가 있으나 로컬 상태 전용이며
  어디에도 렌더되지 않는다. 현재 결과 DTO에는 선수별 득점(GoalRecord) 필드가 없다.
- **순위 / 랭킹**: `rank/index.tsx`, `user/Ranking`은 스텁 화면이다. 순위 계산·조회 로직이 없다.
- 경기 결과 **삭제** API 없음(생성/조회/수정만 존재).

## 5. 아직 확인되지 않은 비즈니스 정책
- 과금/참가비/정산 규칙
- 순위 산정 규칙(승점, 득실차, 승자승 등) — 프런트/백엔드 어느 쪽이 계산하는지 미확인
- 토너먼트 승리팀 진출 처리 규칙
- 선수별 득점 기록(GoalRecord)의 저장 스펙 — 백엔드 DTO 확인 필요
